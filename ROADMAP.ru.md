# Дорожная карта

*[Read in English](ROADMAP.md)*

Область охвата этого репозитория — **только десктоп: Windows + Linux**,
без Android/iOS/macOS. Телефонный клиент планируется как **отдельный
репозиторий со своей дорожной картой**, а не веха в этой.

Каждая веха ниже — список конкретных задач с критериями приёмки. Не
начинайте задачи следующей вехи, пока критерии текущей реально не
выполнены — избегайте параллельной работы сразу над несколькими вехами.

## Текущее состояние — проверено 2026-11-09

**Бэкенд** (`crates/matrix-client`, на `matrix-sdk`/`matrix-sdk-ui`
0.19.1):
- Логин (логин/пароль) и восстановление сессии, персистентность на
  стороне Flutter.
- Синхронизация через `SyncService`.
- Список комнат, в которые вступил пользователь: снэпшот + живые
  обновления.
- Пространства верхнего уровня: снэпшот + живые обновления. Комнаты
  внутри пространства: пока только снэпшот, без живых обновлений.
- Таймлайн комнаты: снэпшот + живые обновления, отправка простого
  текста.
- Ещё не сделано: ответы (reply), реакции, редактирование сообщений,
  поиск, отметки о прочтении, индикатор печати, медиа (картинки/файлы —
  в `matrix-storage` есть только *политика* хранения кэша, без реальной
  загрузки/отображения), проверенное на практике E2EE для уже
  существующей зашифрованной комнаты, голос/видео.

**Интерфейс** (Flutter, `flutter_rust_bridge`):
- Настоящая тёмная тема по собственному визуальному референсу проекта
  на основе Cinny (`design/`), не Material-дефолты.
- Настоящая 3-колоночная десктопная раскладка: боковая панель
  (пространства + навигация) / список комнат / вид комнаты — не
  заглушка.
- Реальный экран есть только у вкладки Home и выбранного пространства.
  Direct Messages, Explore, Search, Inbox и почти весь Settings — явные
  заглушки «Not implemented yet»: осознанное решение, не подделка
  данных, но и не реализовано.
- Логаут работает.

**Платформы:**
- Linux-десктоп: собирается и многократно проверен запуском.
- Windows-десктоп: Rust-воркспейс проверяется в CI на Windows, но саму
  Flutter-сборку под Windows **ещё ни разу не пробовали**. Считайте
  Windows непроверенным, пока кто-нибудь реально не прогонит `flutter
  build windows`.

**Тестирование/CI:**
- 3 Rust-теста (мок-сервер, без реальной сети) + 1 файл виджет-тестов
  Flutter.
- `.github/workflows/ci.yml` гоняет `cargo fmt`/`check`/`clippy`/`test`
  на Ubuntu+Windows, плюс `cargo-deny`/`cargo-audit` — только Rust, само
  Flutter-приложение не собирается и не тестируется.

**Предлагаемая метка текущей сборки: `0.1.0-alpha`.** Ключевая часть
вехи 0.1.0 ниже (настоящий 3-колоночный десктопный интерфейс, без
Material-дефолтов, подключённый к живым данным) по сути выполнена;
оставшиеся пункты этой вехи (панель участников, диалог настроек, DM)
перечислены как открытые задачи ниже, а не выдаются за готовое.

  настоящей Windows-машине (или CI-раннере).

## 0.2.0-alpha — полноценный чат

**Цель:** таймлайн ведёт себя как у настоящего чат-клиента, а не просто
лента простого текста.

- [ ] Ответ на сообщение (reply).
  **Критерий приёмки:** отправка ответа показывает цитату оригинала
  инлайном и корректно round-trip'ится при чтении другим клиентом
  (например, Element).
- [ ] Реакция эмодзи на сообщение.
  **Критерий приёмки:** реакции появляются под сообщением, корректно
  агрегируются по пользователям и видны в другом клиенте.
- [ ] Редактирование отправленного сообщения.
  **Критерий приёмки:** отредактированное сообщение показывает
  «(edited)», история правок хотя бы доступна для получения (полный UI
  истории пока не нужен).
- [ ] Поиск внутри открытого таймлайна комнаты.
  **Критерий приёмки:** ввод запроса подсвечивает/прокручивает к
  совпадениям среди уже загруженных сообщений открытого таймлайна
  (серверный поиск по всем комнатам — отдельная, более поздняя задача).

## 0.3.0-alpha — пространства и роли

**Цель:** пространства и комнаты становятся управляемыми, а не только
просматриваемыми.

- [x] Список пространств верхнего уровня и комнат внутри пространства.
- [ ] Отображение роли участника комнаты (admin/moderator/member) на
  основе power levels.
  **Критерий приёмки:** панель участников показывает метку роли для
  каждого участника, соответствующую реальному состоянию
  `m.room.power_levels` комнаты.
- [ ] Ограничение admin-действий (кик, бан, изменение настроек комнаты)
  по power level текущего пользователя.
  **Критерий приёмки:** пользователь без прав не видит/не может
  вызвать недоступные ему действия; пользователь с правами — может.
- [ ] Создание комнаты или пространства из интерфейса.
  **Критерий приёмки:** комната/пространство, созданные в приложении,
  сразу видны другому клиенту, вошедшему тем же аккаунтом.

## 0.5.0-beta — медиа

**Цель:** картинки и файлы реально работают, а не только текст.

- [ ] Загрузка и отображение картинок инлайном в таймлайне.
  **Критерий приёмки:** картинка, отправленная из другого клиента,
  отображается инлайном, используя кэш `matrix-storage` (без повторной
  загрузки при каждом скролле).
- [ ] Отправка картинки/файла из интерфейса.
  **Критерий приёмки:** файл, отправленный из этого приложения,
  корректно открывается в другом клиенте.
- [ ] Галерея медиа для комнаты.
  **Критерий приёмки:** открытие галереи комнаты показывает все её
  картинки сеткой, загруженные из кэша там, где он есть.
